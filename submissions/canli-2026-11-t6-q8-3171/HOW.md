Construction: a Sherwood covering perfect hash family of strength 6, SCPHF(23; 3171, 8, 6): a 23 x 3171 array of points of the affine space AG(5, 8), each written as the vector (1, P) of GF(8)^6, such that any six columns hold, in some row, six points not on one hyperplane. By the theorem of Sherwood, Martirosyan and Colbourn (2006) it gives CA(23(8^6 - 8) + 8; 6, 3171, 8) = CA(6029136; 6, 3171, 8). Every row is cyclic: row r is j -> a_r^j (j = 0, ..., 3170) for an element a_r = gamma^(e_r) of GF(8^5) = GF(8)[z]/(z^5 + 7z^4 + 6z^3 + 6z^2 + 2), a point being the coordinates of a field element in the basis 1, z, ..., z^4 (gamma and the 23 exponents e_r are in the header of the source file). Multiplying by a_r is a linear map, so each row is an affine progression, and a set of six columns is covered by a row exactly when its shift to column 0 is. The program draws the 23 rows at 4,600 columns. The exact check of that draw found nine sets holding column 0 that no row covers, the least with largest column 3,171 ({0, 453, 1510, 1661, 2718, 3171}), so every uncovered set spans more than 3,171 columns and the first 3,171 columns form the family here.

Built from: nothing. There is no search and no starting array: the rows are the powers of 23 elements of GF(8^5) that the program picks from its seed.

Program: https://github.com/arhancanli/quantavane-covering-arrays/blob/c97dcf0/code/search/cphf6c_v2.c (MIT), built with `cc -O3 -o cphf6c cphf6c_v2.c -lm -lpthread` and run as `./cphf6c 8 23 10 5 4600 23 > draw.txt` (q = 8, 23 rows, time 10 s, seed 5, 4,600 columns, 23 cyclic rows). With as many cyclic rows as rows it runs in its pure cyclic mode, which does no search and does not use the time limit, so the output is the same on every run: draw.txt is byte for byte record/q8_n23_k4600/CA_6029136_6_4600_8.cphf.txt of that repository (rerun on 8 November 2026). Keep the first 3,171 numbers of each of its 23 rows (families/CA_6029136_6_3171_8.cphf.txt there). The file here writes each point id P (five base-8 digits) as the vector (1, P), the integer 32768 + P. Our GF(8) is GF(2)[x]/(x^3 + x + 1) with the codes c0 + 2 c1 + 4 c2, the Conway coding, so no field map is needed for q = 8 (the same rule as table/certificates/CPHF_19_2000_8_6.txt). Every set of six columns was checked exactly twice on our coding: by checker/scphf6_fast.c on the 4,600-column draw, whose uncovered sets all span more than 3,171 columns (record/q8_n23_k4600/), and by checker/fullcheck6.c, a second checker written separately, in mode full on the 3,171 columns, which found nothing uncovered (checks/second/q8_3171_combine.txt). This file was also checked in the Conway field by our own code: all 23 rows are affine progressions, and random sets of six columns and every 6-set of random 30-column windows are covered.
